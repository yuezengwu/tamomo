# 等算力集群：工程效率比与训练成本

更新：2026-09-03。条件计算，尚无 TAMOMO 训练实测。个人设备沿用[成本比较](./apple-nvidia-training-cost-2026-09-03.md)中的额外运行折旧与新增电费口径。

![等算力集群的相交成本曲线](./figures/engineering-efficiency-cost.png)

## 比较口径

两边的**基准总算力相同**，任务和目标质量相同。B300 集群保持固定，横轴只改变 Mac 集群相对 B300 集群的有效训练效率：

    效率比 R = Mac 集群有效效率 / B300 集群有效效率
             = Mac 集群实际有效训练速度 / B300 集群实际有效训练速度

第二个等号建立在两边基准总算力相同的前提下。100% 表示实际速度相同；50% 表示 Mac 集群的速度为 B300 集群一半，完成同一任务需要两倍运行时间。

这里的基准算力使用相同训练任务与数值精度下的参考能力；不能把不同比特精度的宣传 TOPS 相加。若把“算力等同”定义成两边已经实现的最终训练速度相同，那么本图对应的就是横轴 100% 这一点。

## 相交成本线

设等算力 Mac 集群的每小时运行成本为 A，B300 集群的每小时租金为 B。同一任务在固定 B300 集群上的时间为 T：

    B300 任务成本 = B × T
    Mac 任务成本 = A × T / R
    Mac 任务成本 / B300 任务成本 = (A / B) / R
    成本交点 R* = A / B

纵轴以 B300 的任务成本归一化为 100。B300 是水平成本线，Mac 是随效率比上升而下降的曲线，两线在 R* 相交。**高于交点，Mac 成本更低；低于交点，B300 成本更低。**

两边实际工程效率的影响已经集中在横轴的相对效率比中，无需另行假设 B300 集群的绝对效率。

## 图中的数值假设

为构建一组等基准总算力的集群，暂设 **50 台 Mac 的参考训练算力等于 1 张 B300**，即 400 台 Mac 对应 8 张 B300。这个换算尚未实测。

| 参数 | Mac 集群 | B300 集群 |
| --- | ---: | ---: |
| 设备数 | 400 台 | 8 张 GPU |
| 单设备每小时成本 | $0.0875 | $7.89 |
| 集群每小时成本 | $35.00 | $63.12 |
| 小时成本比 | 55.45% | 100% |

单台 Mac 成本为假设的额外运行折旧 0.05 美元，加上新增功率 250 W、电价 0.15 美元/kWh 对应的 0.0375 美元电费。已发生的购机款和自然贬值不分摊给训练。

因此图中的交点是 35 / 63.12 ≈ 55.45%：

| Mac / B300 效率比 | Mac 任务成本指数 | B300 任务成本指数 |
| ---: | ---: | ---: |
| 20% | 277.2 | 100 |
| 40% | 138.6 | 100 |
| 55.45%（约） | 100 | 100 |
| 60% | 92.4 | 100 |
| 80% | 69.3 | 100 |
| 100% | 55.4 | 100 |

在这些假设下，Mac 效率达到 B300 的 60% 时，任务成本低约 7.6%；效率相同时，低约 44.6%。这些数字是条件结果，不是硬件实测性价比。

若等算力换算为每张 B300 对应 k 台 Mac，交点一般为 k × 0.0875 / 7.89。25 台、50 台、100 台分别对应 27.72%、55.45%、110.90%。因此等算力所需设备数必须计入，不能拿一台 Mac 的小时成本与整个 B300 集群比较。

## 硬件升级与交点变化

55.4% 是当前成本假设下的交点。更强的个人设备可以通过减少等算力所需设备数改变交点，协作软件则可以通过减少通信、等待和重算改变实际效率比 R。两者需要分别测量。

固定 B300 能力和价格，设单台 Mac 参考训练能力变为原来的 g 倍，每小时运行折旧与新增电费变为原来的 m 倍，则：

    新的等算力 Mac 数量 = 原数量 / g
    新的集群小时成本 = 原成本 × m / g
    新交点 R* = 原交点 × m / g

| 情景，均为假设 | 个人设备能力倍数 g | 单台运行成本倍数 m | 等成本效率比 |
| --- | ---: | ---: | ---: |
| 当前示例 | 1 | 1 | 55.4% |
| 单机能力翻倍，运行成本不变 | 2 | 1 | 27.7% |
| 单机能力翻倍，运行成本增加 50% | 2 | 1.5 | 41.6% |

这些情景适用于未来已经拥有、可闲时使用的设备；专门采购的新增投入另算。更大内存和更快本地互联只有在减少实际协作损失时才会提高效率，不能仅凭更强芯片断定 R 上升。

未来 NVIDIA 也会升级，必须同时更新集中式方案。例如两边单设备参考能力均翻倍、每小时单设备成本均不变，等算力数量比不变，示例交点仍为 55.4%。

单纯延长同一任务的工期不会自动提高效率。更宽松的期限可以利用更多闲置时段，提高可完成性；休眠且没有新增成本的时间仅影响日历工期。是否降本仍以实际运行消耗及同等质量为准。

复算上述三个情景：

```sh
python3 - <<'PY'
import json
from pathlib import Path
p = json.loads(Path('docs/data/engineering-efficiency-assumptions.json').read_text())
mac_hourly = p['mac_extra_wear_usd_per_hour'] + p['mac_extra_power_kw'] * p['electricity_usd_per_kwh']
base = p['macs_per_b300_at_equal_reference_compute'] * mac_hourly / p['central_usd_per_gpu_hour']
for ability, hourly_cost in ((1, 1), (2, 1), (2, 1.5)):
    print('Mac ability', ability, 'hourly cost', hourly_cost,
          'break-even percent', round(100 * base * hourly_cost / ability, 2))
PY
```

## 测量与边界

效率比应按相同任务和质量目标测量，包含通信等待、负载不均、故障、恢复、无效更新、重算及额外收敛工作。已休眠且没有新增运行成本的时间影响日历工期，不重复增加计费运行时间；醒着等待产生的额外电量与折旧需计入。

本曲线扫描时固定集群每小时成本。若改变工程效率也改变参与设备数、运行折旧或平均新增功率，应同时更新 A。异构设备按照各自实际运行折旧与新增电量累加。

B300 的 7.89 美元/GPU 小时来自 2026-09-03 核查的 [Runpod Pods 定价页](https://www.runpod.io/pricing)，这里作为集群单价参数，**不是已核实的高速互联 8 GPU 集群报价**。云端这里只计 GPU 运行租金，电费已包含，未计额外存储等账单项目。实际比较时替换为目标集群报价。

如果两边都是自有闲置硬件，应将 B300 租金换成其额外运行折旧与新增电费，交点公式不变。内存能否容纳模型、能否收敛和完成期限也需满足。
