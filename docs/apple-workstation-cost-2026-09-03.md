# Apple 新芯片与个人工作台的训练成本

核查日期：2026-09-03。本文区分 Apple 官方规格、厂商性能声明和 TAMOMO 的条件推演；尚未进行新设备训练实测。

## 当前结论

**提高单个工作台的有效训练能力，有机会降低达到相同模型质量的成本。TAMOMO 首先利用已有闲置设备，成本只计训练额外造成的运行折旧与电费。让训练状态留在本机、减少通信和恢复开销、缩短运行时间，都可能降低这两项成本。**

与 NVIDIA 的实际报价对照见 [Apple 与 NVIDIA 训练成本比较](./apple-nvidia-training-cost-2026-09-03.md)。主比较是已有闲置 Mac 的新增运行成本与 GPU 云租金；为训练专门购置或升级硬件时，再单独评估新增投入。

这支持 TAMOMO 继续比较两种组织方式：许多普通设备直接协作，以及由较强单机或少量高速互联设备组成的工作台之间协作。新芯片的数据扩大了可研究范围，尚不能替代成本实验，也没有消除 AGI 训练的算法与能力不确定性。

## 什么改善最可能减少成本

### 1. 内存跨过门槛，可以改变训练的组织方式

沿用[长期价值文档](./long-term-value.md)中的示例配置：BF16 权重和梯度、FP32 主权重及两份 FP32 优化器状态，合计约 16 字节 / 参数。10B 参数对应约 160 GB 固定训练状态，尚未包括激活、临时空间和系统占用。

128 GB 工作台无法单独容纳这组完整状态。256 GB 或 512 GB 配置提供了单机承载的可能，是否能训练仍需验证可用内存、上下文长度、batch 和实现。入门 Ultra 的 96 GB 也没有跨过这个门槛。

如果原方案为了容纳状态而需要跨家庭网络分片，改为本地承载可能减少中间结果传输、同步等待和跨节点恢复。这种收益可能大于单纯增加 GPU 核心数，但它取决于原有瓶颈，属于待验证推断。

大内存仍有限度：同一状态配置下，30B 参数约需 480 GB，留给其他开销的空间已经很少；70B 则约需 1.12 TB。量化推理能够装入的模型规模，不能直接转换成从零全参数训练规模。

### 2. 更高的持续吞吐，可能降低每次训练的电量与折旧

需要测量完成同一目标质量所需的时间，以及这段时间内整机电量。GPU 核心数、内存带宽和制程都提供硬件信息，但无法单独给出完整训练速度。

Apple 的 [M5 与 MLX 研究文章](https://machinelearning.apple.com/research/exploring-llms-mlx-m5)说明了 MLX 使用 GPU Neural Accelerators 的路径，其公开性能比较针对 LLM 推理。GPU 内的 Neural Accelerators 与独立 Neural Engine 也应区分，不能将它们的宣传数字简单相加，作为训练算力。

当前核查的来源没有给出 TAMOMO 所需的新台式机持续训练吞吐、收敛和插座电量对照。因此不把“AI 最高提速若干倍”换算成训练成本下降比例，也不使用产品最大功率作为实际训练平均功率。

### 3. 工作台内部高速互联，可能减少公网承担的同步

Apple 在 [WWDC26 的 MLX 分布式课程](https://developer.apple.com/videos/play/wwdc2026/233/)中展示了 Thunderbolt 5 RDMA、JACCL 与 MLX 的配合。演示使用四台 M3 Ultra，涉及推理和微调，并非新 M5 Ultra 的从零训练成绩。

一种可检验的结构是：单个工作台内承载完整训练 worker，需要时以高速互联分配状态；多个工作台之间使用低通信方法。这样有机会把频繁通信留在本地，把公网用于较低频率的协作。使用已有设备时，成本仍按各设备的运行折旧与新增电费累加；若需要新购设备或线缆，则属于另行评估的扩容决策。

把工作集中到更少节点，也可能让单个节点退出时损失更多进度。恢复是否更便宜，要连同 checkpoint 开销和重算一起测量。

仅升级计算部分会遇到网络上限。假设训练时间的 80% 用于计算、20% 用于无法重叠的通信等待，计算加速 4 倍后，整体只加速 `1 / (0.8 / 4 + 0.2) = 2.5` 倍。如果原来 80% 都是通信等待，整体只加速约 1.18 倍。这是固定工作量、固定通信量的算术示例，说明为什么要先识别瓶颈。

## 怎样判断是否真的便宜

对已经拥有、原本闲置的设备，主模型为：

```text
单项任务成本 = Σ各设备 [额外运行折旧 + 电价 × 新增电量]
新增电量 = 本次训练整机电量 - 同等时段原本闲置状态的电量
单台每运行小时成本 = 额外运行折旧 / 小时 + 电价 × 新增平均功率（kW）
```

运行折旧只计训练额外带来的损耗、剩余寿命或剩余价值减少；历史购置支出和即使闲置也会发生的自然贬值不分摊给训练。尚无可靠折旧依据时，应列出敏感性假设，不把购机价按低训练占用率摊高，也不把没有被使用的闲置时间另行计价。

新增电量应按设备原本会保持的状态计算：本会休眠或关机时，采用休眠或关机基线。时间与电量包含通信等待、故障、失败尝试及重算。多台设备的成本逐台累加，不能用总吞吐配单台电费；已有网络和设备的固定支出不另行分摊。

在达到同等质量的前提下，设较强已有设备的实际达标速度为原来的 `S` 倍，每运行小时的额外折旧为原来的 `A` 倍，新增平均功率为原来的 `B` 倍，电价相同：

- 每项任务的运行折旧变为原来的 `A / S`。
- 每项任务的新增电费变为原来的 `B / S`。
- 若实际速度超过两者，两个成本项都下降；否则需按折旧与电费的权重计算总和。

例如，较强已有设备的每小时额外折旧为原来的 3 倍，新增平均功率为原来的 1.5 倍：

| 假设达标速度相对原设备 | 单次运行折旧变化 | 单次新增电费变化 |
| --- | ---: | ---: |
| 2 倍 | 增加 50% | 减少 25% |
| 4 倍 | 减少 25% | 减少 62.5% |

这组数字是假设示例，不是 Apple 新旧设备的测试结果。它说明更快的工作台可能降低成本，但应依据运行折旧和新增电量判断。

### 专门购置或升级的独立决策

若为了训练新增采购，则需要另算新增现金投入，结合残值、使用期、预计训练量与租用替代方案评估。上文的新品价格适用于这项决策；它不进入已有闲置设备的主成本公式，也不能把采购收益与利用闲置资产的收益混为一谈。

### 更长时间尺度下的硬件变化

未来自然进入闲置设备池的更强工作台，可能减少等算力所需节点数，并降低运行成本。它也可能使更多训练状态留在本地，减少通信与恢复损失。两种收益需要分开测量：前者改变成本交点，后者改变实际协作效率。

固定 B300 基准时，个人设备参考训练能力翻倍、每小时运行成本不变，会使示例交点由 55.4% 降至 27.7%。这组情景及集中式硬件也升级时的变化见[硬件升级与交点变化](./engineering-efficiency-cost.md#硬件升级与交点变化)，不作为新品性能预测。

## 对 TAMOMO 下一步的影响

新硬件使“个人拥有的较强工作台之间协作”更值得纳入实验。较强工作台可能降低通信密度和节点管理成本；普通设备仍可承担适合自身能力的实验与任务。能否在同等质量下共同产生净收益，需要按工作负载验证。

最小比较可按以下顺序进行，先使用可获得的设备，不因新品规格直接扩大采购：

1. 在现有单机上测量小模型基线，记录峰值内存、持续吞吐、达标时间与插座电量。
2. 获得新设备后，按相同模型、数据与质量目标比较；记录为了适配内存而进行的配置调整。
3. 在已有可用设备中，对照“一台较强工作台”与“多台较小设备”，累加达到同等质量的运行折旧与新增电费；分别记录运行时间和日历工期。
4. 先测工作台内部互联，再测工作台之间的真实网络，确认通信、掉线和恢复有没有抵消吞吐收益。

若强工作台降低了同质量运行成本，可以提高其在实验中的比重；若只扩大可训练模型范围，应将结论记为能力提升。对外宣称成本下降时，应同时给出匹配配置、原始日志、训练与原闲置状态电量、质量对照及额外折旧假设。

    print("speedup", speedup, "operating wear ratio", 3 / speedup,
          "incremental electricity ratio", 1.5 / speedup)

    speedup = 1 / (compute_fraction / 4 + 1 - compute_fraction)
    print("compute fraction", compute_fraction, "overall speedup", speedup)

PY
